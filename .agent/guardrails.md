# Guardrails

One line per rule. Born from a real error, so the CLASS of error cannot recur.
Format: `- [G-00N] <imperative rule> — cause: <what broke> (YYYY-MM-DD)`

- [G-001] NEVER write to stdout in the server process — stdout is the MCP JSON-RPC channel and any stray byte corrupts the protocol. Log to stderr only. Enforced by Biome `noConsole` (allows `console.error`) — cause: preventive, this is the single most common way an stdio MCP server breaks (2026-08-14)
- [G-002] NEVER log, echo, or return the API key value from any tool, error message, or stack trace. `riot_key_status` reports presence and validity, never the value — cause: preventive, a leaked key in a transcript is a real credential leak (2026-08-14)
- [G-003] Write erasable-only TypeScript: no `enum`, no `namespace`, no parameter properties, and `import type` for every type-only import. Node strips types without a compiler, so non-erasable syntax fails at RUNTIME, not at typecheck. Enforced by `erasableSyntaxOnly` in tsconfig — cause: preventive, the project deliberately has no build step (2026-08-14)
- [G-004] Derive role from `teamPosition`, never `individualPosition`, and drop participants whose `teamPosition` is empty — cause: preventive, remakes and some queues leave it blank and the row silently pollutes role benchmarks (2026-08-14)
- [G-007] Every peer comparison in LoL is role-conditioned. Never widen a peer pool to "all players" to gain sample size — a bigger n bought with a biased pool is worse than a small honest one — cause: `vision_per_min` was flagged `roleSpecific: false`, so a mid laner's vision score was benchmarked against a pool containing supports (2-3x higher by design). It came out as his single worst metric and headlined the report; against actual mid laners he is fine (2026-08-14)
- [G-006] Never slice, pad or regex a locale-formatted date/time string to extract a part of it, and ALWAYS pass `hourCycle: 'h23'` when a time is going to be read as data. Ask `Intl` for exactly the part you want — cause: `localTime(...).slice(-5)` assumed a 24-hour "HH:MM" tail, but es-AR renders 12-hour with a " p. m." suffix, so the whole hour column in `riot_matches` printed "p. m." (2026-08-14). Strengthened after hitting the other half of the same class: a bare `toLocaleString('es-AR')` in an analysis script printed an 18:05 game as "06:05" — the period is dropped, not mangled, so the output looks valid and is off by twelve hours (2026-08-16)
- [G-011] Sweep EVERY arbitrary parameter an analysis rests on, not only the one that is convenient to sweep, and report the sweep next to the finding — cause: the minute-14 conversion finding shipped with a four-band gold sweep as its robustness evidence while `STATE_MINUTE = 14` was never swept at all; swept, the sign of the gap flips at 12 and 16, its two immediate neighbours, and the neighbours hold more games in the binding bucket than 14 does. The band was the weak test and it was the only one run (2026-08-16)
- [G-012] A robustness or consistency check must reject the degenerate case EXPLICITLY and never bless a finding by agreement alone — "every band agrees" is not evidence when what they agree on is zero — cause: `conversionIsRobust` returned `true` for a gap of exactly 0, because `Math.sign(0)` is 0 and a one-element set passes the agreement test; its test pinned that behaviour with a fixture where both rates were 1.0, so the suite was green for the wrong reason. Sibling of G-005: there the statistic was undefined, here it is defined and empty (2026-08-16)
- [G-018] Source files carry no control characters beyond tab and newline; a control byte that is genuinely wanted is written as an escape (`'\u0000'`), never as a raw byte. Machine-checked by `tests/encoding.test.ts`, which scans `src/`, `tests/` and `scripts/` — cause: a literal NUL ended up inside a string in `matchups.ts` (`join('\0')` where a space was intended). It was functionally harmless and completely invisible to the verify chain — tsc, Biome and Vitest all passed, because none of them looks at bytes — and surfaced only when git classified the file as BINARY on commit, which would have broken diff and blame on that revision forever in a public repo (2026-08-16)
- [G-017] Derive the extent of a sampled series from the SAMPLES' OWN TIMESTAMPS, never from how many there are, and never let a boundary that falls outside the data silently drop a whole bucket — clamp the boundary to the last sample that exists — cause: `phaseSplit` computed game length as `frames.length - 1`, but a timeline appends a final PARTIAL frame, so a 24:01 game reported 26 frames and was treated as 25 minutes long; minute 25 had no frame, the lookup returned null, and the `continue` threw away the entire 14-25 phase without a word. The bug only fired for games ending just after a minute boundary, so it looked like missing data rather than a defect (2026-08-16)
- [G-016] Champion names have three spellings in this project — Riot PascalCase (`TwistedFate`), op.gg spaced (`Twisted Fate`) and the vault kebab slug (`twisted-fate`). Never compare them raw: go through `championKey` and add a case to its test when a new source appears — cause: a comparison script matched op.gg rows against vault filenames with a naive lowercase-and-hyphenate, so every multi-word champion silently failed to join and was reported as a data discrepancy in the vault. The vault was correct; the join was not (2026-08-16)
- [G-015] Before declaring two aggregates from different sources to be in disagreement, establish that they share a SCOPE — window, queue set, remake policy, account, and whether the source counts by season or by a last-N snapshot. Reconcile on a case where they must agree before trusting a case where they differ — cause: reported "8 of 19 matchup notes and 2 of 4 champ notes disagree with the derived record" and wrote it into the vault's schema changelog as justification for a design change. All of it was scope mismatch of my own making: the notes were a last-20-games op.gg snapshot and I compared them against a full-season derived count, my cache was missing 6 flex games, and op.gg excludes remakes while my query included them. Corrected: 18 of 19 matchup notes match their source EXACTLY, and all 8 champion totals reconcile to the game once the three differences are accounted for. The vault was right and the comparison was wrong (2026-08-16). Strengthened the same day: the rule also covers a SINGLE statistic carried from one scope to another — "wardType is UNDEFINED on 27% of placements" was measured over every player in the corpus and written into a module comment as a limit on HIS vision analysis; checked, all 2088 of those belong to other players and zero to him, so the caveat was real about the corpus and false about the subset it was attached to (2026-08-16)
- [G-014] A sentinel that means "no measurement" must be mapped EXPLICITLY across every storage boundary, in both directions, and the column must allow it. Never let `Number(row[col])` be the read path for a value that can be absent — cause: this codebase deliberately uses `NaN` for "no measurement, and do not dare report it as zero" (G-005), but `node:sqlite` binds `NaN` as `NULL`, so the first evaluation of an empty out-of-sample window died on a `NOT NULL` constraint — and had the column been nullable it would have been worse: `Number(null)` is 0, so a carefully preserved "unknown" would have been read back as the exact value G-005 exists to prevent (2026-08-16)
- [G-013] A registered hypothesis may be evaluated ONLY under the exact analysis spec it was registered with: hash the spec at registration and refuse to evaluate against a different hash. Every spec field is required and explicitly listed in the canonical form, and a type-level assertion fails the build if a new field is added without being listed — cause: born from G-011. An out-of-sample evaluation whose minute, band, role, queue, account or outcome variable can be re-chosen at evaluation time inherits exactly the researcher degrees of freedom that manufactured the finding, which defeats the entire purpose of the ledger (2026-08-16)
- [G-010] Never rewrite a tracked source file through an external script's default text mode on Windows — it silently converts every `\n` to `\r\n` and rewrites the whole file. Use the Edit tool for source edits; if a script must write, open it with `newline=''` (Python) or write bytes — cause: annotating the 18 metrics with a Python `io.open(p,'w')` turned the entire file CRLF, so `biome check` failed on the whole of `metrics.ts` rather than on the three-line change actually made (2026-08-16)
- [G-008] Every metric must declare whether it is measurable BEFORE the outcome is decided. Never report an unconditioned mean over a metric that is downstream of winning (KDA, full-game CS/min, damage/min, vision score, duration): condition on the result, or fix the game-state stratum — cause: the benchmark reported him ahead in 17 of 18 metrics over 36 games and headlined "your laning is not the problem", but the mean was dominated by the games he snowballed (enemy mid KDA 1.10 in his wins). Conditioned on the result he LOSES the matchup in most of his 17 defeats, and his only pre-outcome metric, CS@10, shows zero discrimination between wins and losses (67.8 vs 69.5) (2026-08-16)
- [G-009] Never compute a percentile, mean or effect size over a Riot `challenges` field without first checking its actual distribution — several are 0/1 flags or ordinals, not magnitudes — cause: `laningPhaseGoldExpAdvantage` is binary (0 in 24 games, 1 in 12, and identical to `earlyLaningPhaseGoldExpAdvantage` in all 36), so "percentil 97 en ventaja de oro+XP en línea" was a percentile over a flag: it said he trips the flag more often than his opponents, never by how much (2026-08-16)
- [G-005] Never let a single statistic decide whether a gap exists. Any ranking built on an effect size must carry an explicit fallback for the degenerate case (zero or near-zero pooled variance), and must never report "no difference" merely because the statistic was undefined — cause: `cohensD` returns NaN when both samples have zero variance, and `severityOf` mapped NaN to 'parejo', so a player farming 5.0 CS/min against peers at 7.0 was reported as even — the exact gap the tool exists to find (2026-08-14)
- [G-019] A confidence, coverage or "how sure am I" rung must be derived from the SAMPLE SIZE, never from the share of an estimate that a source contributes — a share is 1 whenever there is only one source, at any n. Any ladder read off a share needs an explicit branch for "there is nothing to blend with" — cause: `confidenceOf` returned `mayormente_propio` ("your record rules") for a SINGLE game whenever no op.gg prior existed, because `shrink` sets `ownWeight` to 1 with no prior to mix in, and the ladder read the rung off that share alone. It is the exact failure the ladder was written to prevent — an n=1 number wearing a confident label — and it stayed invisible until the coverage tracker ran on a machine with no vault mounted, where every prior is absent. That is also the state the MAIN starts in (2026-08-18)
- [G-020] A wiring test must assert the NAMES of what it expects, never the count — cause: `pnpm smoke` asserted `tools.length !== 7` and had been silently wrong since `riot_backfill_timelines` made it 8. A count cannot say which tool went missing, and it goes stale the moment anyone adds one, so the check that exists to catch a broken registration was itself broken and reported a passing server as a failure (2026-08-18)
- [G-021] An OPTIONAL side effect must be wrapped in the failure mechanism it actually uses, and a try/catch around `spawn` is not one — a missing binary arrives as an asynchronous 'error' event, so the synchronous catch runs on nothing and the unhandled event kills the process — cause: `lol ui` opens the browser as a convenience, with a try/catch and a comment saying a failure was not an error. On a machine with no `xdg-open` the whole UI died on boot, after having already printed its URL. The code claimed a guarantee the language does not give it that way, and only running it on such a machine showed the difference (2026-08-18)
- [G-022] Code that ships as a STRING — inline client JS, a generated script, anything the verify chain only ever sees as text — must be parsed by a test, and any backslash escape inside a template literal must be doubled. Inside a template literal `\n` is a real newline, not the two characters — cause: the UI's client script is built in a template literal, and a string written as '\n' came out split across two physical lines, which made the whole script unparseable. The page loaded, did nothing at all, and tsc, Biome and Vitest were ALL green, because none of them looks inside a string. Found only by compiling the script with `new Function` in a test, which is now what pins it. Sibling of G-018: same blind spot, different byte (2026-08-18)
- [G-023] A generated fragment that carries CLASSES and no inline presentation is only half a component: whoever embeds it must also embed its stylesheet, so export the CSS beside the builder and assert by test that every class the builder emits has a rule. Never copy the rules into the second host — cause: the UI reused `deathMapSvg` and `goldCurveSvg`, which was the right call, but not the CSS they depend on; it lived only in the static page's own `<style>`. Every fill fell back to the browser default, so the death map rendered as a SOLID BLACK SQUARE that correctly counted 188 deaths and displayed none of them. tsc, Biome and Vitest were all green — the SVG was valid, the numbers were right, and nothing in the verify chain looks at whether a class has a rule. Found by screenshotting the page with headless Chromium (2026-08-18)
- [G-024] Never hand-quote an argument you pass through `spawn`'s argv array: the runtime does its own escaping on Windows, so your quotes arrive as literal `\"` characters inside the value. Escape for the parser that will actually read it — and if that parser is a shell, say so and use `windowsVerbatimArguments` — cause: `lol ui` wrapped the browser URL in quotes to protect a hypothetical `&` from cmd. Node escaped those quotes when building the command line, `start` received `\"http://...\"` and Windows popped a dialog saying it could not find a FILE by that name. The server was running and reachable the whole time, so it read as "the UI is broken". A defence against a problem that did not exist broke every real launch, on the one platform the change could not be tested from (2026-08-18)
- [G-025] A trend that goes on the record must be FITTED over every point, never read off the first and last value of the series, and a sign that flips across the smoothing window is no trend at all — cause: the growth curve reported his CS@10 gap drifting -0.147 per game, computed as (last - first) / games over a rolling mean. Adding three games to a 36-game series moved it to -0.040, a 3.7x swing from the endpoint alone; fitting a line over all 39 points gives +0.030, the OPPOSITE SIGN, and the window sweep runs +0.083 / +0.030 / -0.015 over 5 / 10 / 20. The finding "his lane edge is decaying" was an artefact of where the series happened to stop, and it was two days from being frozen into the ledger as a dated prediction (2026-08-18)
- [G-018 extended 2026-08-18] The byte scan covers `.agent/` as well as `src`, `tests` and `scripts` — cause: G-018's own line in this file carried a raw NUL where it meant to show the escape, so git classified guardrails.md as BINARY and the ledger of rules lost line-by-line diff and blame. The rule was written correctly and the file broke it
- [G-026] A tool whose scope is the working directory must be given that scope explicitly, and SILENCE from a checker is never a pass: require it to state what it checked (files, tests, rows) before believing it — cause: a `cd` into another directory persisted across shell calls, so `biome check .` ran where there was nothing to lint and printed NOTHING with exit 0. Read as "the warnings are gone", it was about to be reported as a clean run; from the repo the two warnings were still there. Everything that reports "0 problems" can also be reporting "0 files" (2026-08-18)
- [G-027] SYNC BEFORE REGISTERING. Any dated act that counts games — a registration, a declared gap, a baseline boundary — must run on a cache that has just been synced, because the count is taken from what is downloaded and not from what was played — cause: `team_state_dominates` was registered while the key was expired, so the cache stopped at 2026-08-16 and its declared hole recorded 3 states. Six games from 2026-08-17 existed and fell inside the same window: the true hole was 7. Retired at n=0 and re-registered as `team_state_dominates_500g` with an identical spec hash and an exact gap, which cost nothing only because nothing had accrued yet (2026-08-18)
- [G-028] A claim that NAMES A SLICE — this phase, this champion, this minute, this queue — must be measured on the OTHER slices before it is registered, and it is only about that slice if the others disagree. The control slices go next to the finding, like the sweep — cause: "the deaths gap between wins and losses peaks in the mid phase (2.4x against 1.6x in lane)" was queued as the next hypothesis. Rebuilt as a rate per minute of exposure and framed as a prediction, the same split gives +0.24 in the laning phase, +0.27 in the mid phase and +0.31 in the close: every phase, every gate and every threshold is positive, so what the number says is "he wins the games he dies less in", which is a tautology wearing a phase label. The peak was duration, and nothing was registered (2026-08-19)
- [G-029] An UNKNOWN quantity must not be read as zero when the decision it feeds is IRREVERSIBLE — carry the absence in the type and make the irreversible branch refuse it — cause: the pre-game briefing decides which registered hypothesis it may show by how far its verdict is out of reach, `nNeeded - n`, where `n` is the out-of-sample count of the last evaluation. A row that had never been evaluated arrived as `n = 0`, so its shortfall was the whole of `nNeeded`: it looked further from a verdict than any evaluated row and was therefore the FIRST one spent. Reading the ledger before evaluating it made the briefing maximally talkative, which is exactly backwards, and an exposure cannot be undone once he has read it. `n` is `number | null` now and a null is withheld with its own reason. Same substitution G-005 and G-014 already ban, and the only reason it needed its own line is the irreversibility: a wrong number here is not corrected by the next measurement, it is baked into the corpus. Found by running `lol antes` against a seeded cache instead of trusting the tests (2026-08-19)
- [G-030] Any function that writes to, or reads the state of, a REAL location outside the database — `.env`, the artwork folder, anything on disk the user owns — must take that location as a parameter defaulting to the real one, exactly as `openDb(path)` does. A test that cannot redirect it either clobbers his files or depends on them — cause: two in one session. `writeKey` wrote to the project's `.env`, so the first test of it would have overwritten his REAL Riot key with `RGAPI-nueva` on every `pnpm verify`, silently, and he would have found out as a 401 the next time he synced. And `upkeepState` counted PNGs in the real `data/img`, so its test passed on a machine that had never downloaded the artwork and failed on one that had — it failed here the moment the download ran, which is how it was caught. Both now take the path; production never passes it (2026-08-19)
- [G-031] A checker whose real errors are buried under routine informational diagnostics is a checker nobody can read: cap the noise (`biome check . --diagnostic-level=warn`) so an error is visible, and never conclude "it just prints that" from a truncated report — cause: `pnpm verify` started failing with `× Some errors were emitted` and no visible cause. The output ended in "The number of diagnostics exceeds the limit allowed. Diagnostics not shown: 94", and the ~110 `useLiteralKeys` infos this codebase deliberately keeps had pushed the ONE real error — a formatting diff in `routes.ts` — off the end. It took a bisect against a clean HEAD to find that the two `biome.json` schema warnings at the top were not the cause. Sibling of G-026: that one is silence read as a pass, this one is noise hiding a failure, and both end with a report nobody can act on (2026-08-19)
- [G-032] A ranking always has a first element, so "the top of the sorted list" is NOT evidence that anything stands out: read the headline off an explicit severity or threshold, and say nothing when nothing qualifies — cause: the new reading panel captioned "lo que mejor hacés: Placas de torreta" and "donde más perdés" from `strongest[0]` and `weakest[0]`. On a corpus where every metric tied at exactly zero difference — and where all four were reported as "no medible" for want of variance in the same breath — it still printed both captions with total confidence. A label that cannot ever be absent is a label that carries no information, and this one was on the first thing he reads (2026-08-19)
- [G-033] A rate the code REFUSES TO STATE must not be drawn either: whatever suppresses the number suppresses the bar, the slice and the position, because a shape is read before the text beside it — cause: the tag split correctly withheld the percentage below `MIN_GAMES` and then drew the proportion bar anyway, so "salía igual · 1W-1L" rendered a half-full bar that looks exactly as solid as a half-full bar over fifty games. Found by looking at the screenshot (2026-08-19)
- [G-034] A sweep that returns the SAME value at every setting is not a passed sweep, it is a sweep wired to something the knob does not touch: assert that the values differ before believing the agreement — cause: the panel's growth sweep reported +0.1538 at windows 5, 10 AND 20 and rendered a confident "same sign in all three". It was fitting over the RAW per-game gap, which no smoothing window can change, so the three runs were arithmetically identical by construction. It looked like the strongest possible evidence of stability and was evidence of nothing. Caught by reading the three identical numbers in the payload, not by any test — the tests asserted the sweep's SHAPE (three windows, finite slopes) and every one of them passed (2026-08-19)
- [G-035] A guardrail born from a wrong NUMBER must be encoded where that number is produced, and the entry is not finished until it is — a rule that only lives in this file protects nothing but the next reader's memory — cause: G-009 was written the day "percentil 97 en ventaja de oro+XP en línea" shipped over a Riot `challenges` field that is 0 in 24 games and 1 in 12. - [G-036] A DECLARATION about an external source's data cannot be checked by the compiler, so re-check it against the sample at read time and demote loudly when the data disagrees — cause: G-035's fix rests on someone classifying eighteen metrics correctly from a guardrail written about two of them, which is the same trust that failed the first time. `looksBinary` now re-reads every declared magnitude and reports the disagreement by name; on the first run it caught a third metric nobody had flagged (2026-08-20)
- [G-037] A reader that returns an EMPTY result must say why, and "the source is absent" must never share a return value with "the source is here and I could not read it" — cause: `loadPriors` returned `[]` for a missing file, a CRLF file and a renamed column alike, and documented the first as normal. - [G-038] A chain of comparisons that ends in a claim must REFUSE the degenerate case in its first branch, never leave it to the fallback — cause: `lol growth` printed "tu línea se movió MÁS que la de los rivales (neto +0.000 por partida)" over two curves that had not moved at all. G-012 again, in a second place, because the rule was written about one function instead of about the shape (2026-08-20)
